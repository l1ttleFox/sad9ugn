# 8. Геополитический бонусный модуль

Статус: **отдельный research-сценарий (TEAM_*), не часть MANDATORY_STRESS** (STARTER_README §31). Автоматически складывать MANDATORY_STRESS + high demand + геополитику запрещено без объявления отдельного combined-сценария (CASE_RULES §6). Числовые результаты — `results/geopolitics/` (P05, прогон WP3 волна 2 на FINAL-плане, §8.3).

## 8.1 Принцип: причинная цепочка

Модуль не предсказывает политику. Он показывает воспроизводимую цепочку влияния гипотетического события на расчёт:

```text
событие → параметр цены (или объёма/lead time) → пересчёт модели → расходы и решения → эффект на стороны
```

Минимальный интерфейс сценария (STARTER_README §31) — по формату TEAM_* из `configs/`:

```text
event_label                    # метка условного события
affected_source_or_cost_component  # канал/компонент, параметр которого меняется
start_period / end_period      # YYYY-MM окно действия
multiplier_or_range            # множитель или диапазон (сценарий/интервал вместо ложной точности)
source_or_TEAM_ASSUMPTION      # основание: откуда взят множитель
```

Обязательные свойства: export параметров сценария и возможность восстановить control values (возврат к CASE_INPUT одним переключением); сохранение scenario_id, plan_id, версии входов и результата (STRESS_PROTOCOL «Изоляция и воспроизводимость»).

## 8.2 Реализованный условный сценарий GEO-1 «Торговые ограничения» (`TEAM_GEO_CHANNEL_A`, риск R10)

**Событие (условное, не прогноз):** введение экспортно-лицензионных ограничений в регионе базирования наземной инфраструктуры канала A поднимает стоимость доставки через Earth-Core — `event: geo_channel_a_tariff`.

**Mapping на параметр:** `variable_price_multiplier` канала A = **1.20** на окно 2038–2039: цена 6.2 → **7.44 млн у.е./т** (TEAM_ASSUMPTION; верхняя граница диапазона k ∈ [1.15, 1.40] — по аналогии с +25% шоком MANDATORY_STRESS; рабочий сценарий — среднее значение 1.20). Множитель применён ОДИН раз через `variable_price_multiplier` (D8.4: дублирующий плоский override из YAML удалён; тест `test_geo_single_application_and_restoration`). Резервные тарифы, CAPEX и цены прочих каналов не затронуты (проверено тестом).

**Пересчёт (тот же `run_plan`, новый TEAM_* сценарий):**
1. `VariablePayment = price × k × Q_pay`, где `Q_pay = max(Q_order, 0.70 × Q_reserved_period)` (CR §5) — рост расходов пропорционален оплачиваемому объёму, включая TOP-минимум: при высоком резерве A шок усиливается TOP-переплатой.
2. Материальный баланс и SL не меняются (ценовой шок без объёмного): дефицита нет — эффект чисто экономический.
3. Меняется **относительная выгодность каналов**: B (8.9) становится конкурентоспособнее подорожавшего A (6.2 × k ≥ 7.13 уже при k = 1.15), D (3.0, после ввода) и опцион C выигрывают в ценности.

## 8.3 Результаты прогона (до/после, FINAL_BASE; `results/geopolitics/P05_*`)

| Показатель | До (BASE) | После (GEO ×1.20, 2038–2039) | Эффект |
|---|---:|---:|---:|
| TotalCost, млн у.е. | 12411.71 | 12882.90 | **+471.19** |
| PV расходов, млн у.е. | 9961.31 | 10299.23 | **+337.92 (+3.4%)** |
| SL_total / shortage | 1.000 / 0 | 1.000 / 0 | без изменения (0 нарушений) |

Проверка арифметики: +471.19 = Δцены 1.24 млн/т × Q_pay,A(2038–2039) = 1.24 × 380 т (заказы A 190+190 > TOP-минимума 133 — платёж по заказу).

**Порог переключения A→B (reverse-логика):** перенос объёмов на B выгоден при цене A выше 8.9 млн/т, т.е. при k > 8.9/6.2 ≈ 1.44 — за пределами рабочего диапазона [1.15, 1.40]; кроме того, перенос упирается в TOP A = 0.70×190 = 133 т (объёмы ниже TOP оплачиваются даже при нулевом отборе; (7.44−8.9)×ΔQ < 0 — переключение убыточно). Поэтому дешёвой физической меры против тарифного шока нет (§11.1 R10) — эффект остаётся у заказчика.

**Эффект на стороны** (`P05_parties.csv`, по годам):
- оператор (заказчик): +337.92 млн PV расходов при неизменном физическом плане; решение о переключении каналов экономически не оправдано (порог k > 1.44);
- критические потребители: SL не затрагивается (1.000) — ценовой шок без недопоставки; при комбинированном сценарии (цена + объём) приоритет аллокации сохраняется;
- поставщик A: +471.2 млн выручки при том же объёме (2038: 1177.98 → 1413.57; 2039: так же +235.6 млн/год); риск потери доли только при k > 1.44;
- поставщик B/C/D: рост относительной привлекательности (B — с 8.9 против 7.44; D — 3.0), потенциальный рост заказов при более высоком k;
- финансирующая сторона: CAPEX-лимиты не затронуты (платёж 2036-06 вне окна шока), но рост операционного бюджета давит на PV и усиливает аргументы диверсификации (опционная стратегия G4, §12.3).

**Комбинированный сценарий (явно объявленный, отдельный):** `TEAM_GEO_A_MANDATORY_COMBINED` на FINAL_STRESS — цена A 2038–2039 = 6.2 × 1.25 × 1.20 = **9.30 млн/т** (ровно по одному разу каждого шока; тест `test_geo_combined_no_double_count` проверяет ≠ 9.30×1.20), B = 8.9 × 1.25. PV combined = **11920.85** млн (+422.40 к FINAL_STRESS 11498.45; +1959.54 к BASE 9961.31), TotalCost 15112.25, SL 1.000, 0 нарушений. Эффекты раздельно: mandatory-адаптация +1537.14 млн PV (к BASE), geo +337.92 (на фиксированном плане); простая сумма +1875.06 против combined-дельты +1959.54 к BASE — расхождение +84.5 млн объясняется взаимодействием шоков через TOP/запас в адаптированном плане (раскрыто в `P05_summary.json`), двойного начёта нет. В P01 combined НЕ включался.

**Восстановимость (контроль):** повторный прогон BASE после события = исходные числа ПОБАЙТОВО (yearly_balance и financial_breakdown идентичны — тест), цена A в каталоге снова 6.2, sha256 CASE_INPUT-файлов не изменились (`restoration.ok = true`) — глобальное состояние не мутировано. Экспорт параметров: `geo_event.json` (event_id, канал, исходная/новые цены по годам, коэффициент, период, sha256, diff эффективных цен 2035–2040).

## 8.4 Оговорки (обязательны при любом использовании модуля)

1. **Условные сценарии, не прогноз политики.** Модуль отвечает на вопрос «что будет с расчётом, ЕСЛИ параметр изменится в k раз», а не «когда и почему изменится политика». Вероятности событий не заявляются: при отсутствии статистики используется сценарный/интервальный подход вместо ложной точности (STARTER_README §31, STRESS_PROTOCOL).
2. **Рыночная цена топлива ≠ агрегированная цена доставки.** В кейсе variable cost канала уже включает доставку в узел (CASE_RULES §5); модель агрегирована по тоннам условного ресурса. Поэтому геополитический множитель трактуется как шок **агрегированной цены канала** (топливо + доставка), а не как прогноз биржевой цены компонента топлива.
3. **Изоляция от обязательных сценариев.** GEO-* не накладывается на MANDATORY_STRESS и high/low demand автоматически; combined-вариант объявляется отдельным TEAM_* с явным правилом комбинации шоков.
4. **Восстановимость.** Все изменения — множители сценария поверх неизменного CASE_INPUT; после прогона control values восстанавливаются, исходные данные не мутируются (`apply_scenario` возвращает новый CaseData, core_api.md).
5. **Трассируемость основания.** Каждый множитель — TEAM_ASSUMPTION с источником/обоснованием и областью действия (CASE_RULES §3); выдавать его за CASE_INPUT запрещено.
