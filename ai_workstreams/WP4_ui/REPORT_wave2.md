# WP4 — отчёт по волне 2

Дата: 2026-09-19. Статус: **завершено**.

## Что закрыто из списка «Что осталось»

1. Services-слой переключён на реальный публичный API WP1: load_case → load_plan/load_saved_plan → load_scenario → run_plan; экспорт идёт через export_results, каталог планов — через save_plan/load_saved_plan. USE_ENGINE=True, версия фактического результата 0.3.0-wave3.
2. Полный список constraint_checks берётся только из RunResult.checks ядра. UI больше не строит успешные проверки из violations и останавливается с явной ошибкой, если полный список отсутствует.
3. Подключены все 10 TEAM_*-сценариев. Сначала просматривается configs/team/, затем резервный каталог ai_workstreams/WP3_stress_risk/configs/team/. origin/wp3-stress на момент работы не содержал публикации волны 2 в configs/team/, поэтому проверен резервный путь.
4. Автообнаружение демонстрационных планов ищет FINAL в results/plans/ и каталоге WP2. origin/wp2-strategy на момент работы не содержал FINAL, поэтому кнопка автоматически предлагает S10.json; после публикации FINAL код менять не требуется.
5. Сохранение в results/plans/ выполняется парой: <plan_id>.json по plan_format.json и отдельный <plan_id>_contracts.json по решению D4. Повторное открытие восстанавливает план и реестр договоров; файлы *_contracts.json не попадают в список планов.
6. CSV и XLSX формируются из того же кэшированного RunResult ядра. ZIP CSV содержит шесть таблиц и метаданные; ZIP XLSX содержит results.xlsx и export_meta.json.
7. Геополитический модуль принимает event_label, канал, коэффициент цены и период; исходные CASE_INPUT не меняются. Кнопка восстановления удаляет исследовательский результат и возвращает кэшированный контрольный BASE.
8. Обновлена docs/ИНСТРУКЦИЯ.md: полный маршрут эксперта от загрузки до повторного открытия и экспорта. Русские сообщения ошибок, единицы и текстовые статусы нарушений сохранены.
