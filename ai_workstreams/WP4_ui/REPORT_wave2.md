# WP4 — отчёт по волне 2 (подготовка, интеграция ожидает зависимости)

## Состояние

Волна 2 **не завершена**. Ветка `wp4-ui` уже содержит WP1 волну 1 (`09ae7ea`), но финансовый блок, полный реестр ограничений, риски, сравнение и экспорт в `src/engine/` ещё являются заглушками `NotImplementedError`. `origin/wp2-strategy` пока не содержит FINAL-планов; `origin/wp3-stress` содержит протоколы, но не TEAM YAML. Поэтому реальный полный пользовательский прогон, числовые примеры до/после, сверка интерфейса с экспортом ядра и критерий восстановления BASE после геосценария пока не могут быть доказаны.

## Подготовлено в своей области файлов

- `app/services.py`: автоматический выбор ядра после завершения обязательных модулей WP1; частичное ядро не подменяет финансовые и стрессовые показатели. Публичный маршрут `load_case` → `load_plan` → `load_scenario` → `run_plan`, кэширование контрольного набора и прогонов, преобразование dataclass/dict в RunResult, русская диагностика ошибок. Если ядра нет, остаётся явно обозначенный мок-режим.
- `app/services.py`: каталог `results/plans/` с безопасным сохранением/повторным открытием, обнаружение TEAM YAML, условный экспорт через `export_results` в CSV/XLSX и исследовательский ценовой сценарий без изменения CASE_INPUT.
- `app/main.py`: элементы сохранения и загрузки из каталога, автоматические кнопки FINAL при появлении планов WP2, редактирование уже загруженных заказов, резервов и инвестиций, состояние ядра, сценарий/период на странице, форма геополитического события и восстановление контрольного вида.
- `requirements.txt`: добавлен `openpyxl` для XLSX.
- `docs/ИНСТРУКЦИЯ.md`: одностраничный маршрут эксперта и явное описание текущего демо-режима.

## Проверено

- `python -m compileall -q app` и Streamlit `AppTest`: семь разделов работают без исключений при наличии только частичного WP1; интерфейс остаётся в помеченном демо-режиме.
- `python -m pytest tests/test_engine_wave1.py -q`: 26 тестов WP1 прошли.
- Настоящий `run_plan` WP1 волны 1 обработан адаптером: 72 месяца, 6 годовых строк; финансовых строк и проверок в результате пока 0. UI не показывает этот неполный результат как финальный.
- Тестовый двойник публичного API подтвердил вызовы `load_case`, `load_plan`, `load_scenario`, `run_plan`, кэширование (повторная вкладка не вызывает второй прогон), экспорт и геосценарий. Это проверка границы API, а не реальной модели WP1.
- Каталог планов проверен в изолированной временной директории: сохранение, повторное открытие, запрет `../`.
- Три файла `tests/examples/invalid_plan_examples` дают русские ошибки валидации, без traceback.

## Что осталось после публикации зависимостей

1. После WP1 волн 2–3 сверить экспорт и заполнение финансов/ограничений с адаптером в `app/services.py`; проверить реальный запуск всех семи разделов на чистом клоне. Вложенный `RunResult` волны 1 уже преобразуется в плоский контракт UI. В текущем `Violation` нет поля `passed`, поэтому WP1 должен предоставить полный список пройденных и нарушенных проверок по `result_format.json`; UI не будет выдумывать успешные проверки.
2. Добавить и проверить FINAL-планы WP2 в каталоге и TEAM-сценарии WP3 в переключателе.
3. Изменить заказ, резерв и инвестицию в реальном плане, записать два числовых примера «до/после» для баланса, стоимости и нарушений.
4. Сверить пять чисел интерфейса с CSV ядра; проверить XLSX и время прогона < 3 секунд.
5. Прогнать геосценарий и после восстановления сравнить BASE с исходным результатом до символа.
