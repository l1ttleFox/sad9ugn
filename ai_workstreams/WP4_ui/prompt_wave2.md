# WP4 Волна 2 — Интеграция UI с расчётным ядром

## Роль
Ты — fullstack разработчик. Ядро WP1 готово (ветка `wp1-core`), моки UI (волна 1) работают. Задача: заменить мок-слой реальным ядром, обеспечить полный пользовательский сценарий из кейса и финальные экспорты. Это критерии 19–20 жюри (10 баллов) + «эксперт может открыть решение и пройти основной сценарий по краткой инструкции».

## Зависимости
- `wp1-core` (ядро, run_plan, export_results, save/load_plan, compare_scenarios).
- `wp2-strategy` (FINAL-планы в results/plans/ — для демонстрации «открыть готовый план»).
- Свой REPORT_wave1.md.

## Задание
1. **Переключить services-слой:** `get_run_result` → `run_plan(load_case(...), load_plan(...), load_scenario(...))`; обработка исключений ядра — сообщения на русском в UI (st.error с параметром и периодом).
2. **Полный пользовательский сценарий без разработчика** (проверить руками, записать шаги в `docs/ИНСТРУКЦИЯ.md`):
   загрузить контрольный набор → открыть/создать план → изменить решение (заказ, резерв, инвестиция) → пересчитать → увидеть нарушения с годом/величиной/причиной → переключить BASE↔STRESS → сравнить → сохранить план → повторно открыть → выгрузить CSV/XLSX.
3. **Сохранение планов:** каталог `results/plans/` в UI (список сохранённых, загрузка, «сохранить как»); формат plan_format.json.
4. **Экспорт:** кнопка выгрузки полного конверта (export_results ядра): yearly_balance, source_schedule, inventory_trace, financial_breakdown, constraint_checks, risk_register + meta (scenario, периоды, единицы, assumptions_reference). CSV обязательно, XLSX если openpyxl доступен. Проверка: числа UI == числа файлов.
5. **TEAM_*-сценарии** (из `configs/team/` WP3): добавить в переключатель с пометкой «исследовательский», включая геополитический модуль (ввод event_label, канал, коэффициент, период → пересчёт → эффект; кнопка «восстановить контрольные цены»).
6. **Производительность и стабильность:** пересчёт < 3 сек; кэширование load_case; отсутствие повторных пересчётов при переключении вкладок.
7. **Доступность:** подписи единиц везде (т, млн у.е., доли %); таблицы читаемы без цвета; нарушения дополнительно помечены текстом/иконкой; сценарий и период видны на каждой странице.
8. **Демо-данные:** кнопка «загрузить FINAL BASE / FINAL STRESS» (планы WP2) — эксперт сразу видит работающую стратегию.

## Что НЕ делать
- Не менять расчётную логику ядра (баги → REPORT оркестратору).
- Не хардкодить числа результатов в UI — только из run_result.

## Формат результата
- Обновлённый `app/`, `docs/ИНСТРУКЦИЯ.md` (пошагово для эксперта, 1 страница), `REPORT_wave2.md`.
- Git: `wp4: интеграция UI с ядром` → push `wp4-ui`.

## Критерии приёмки
1. `streamlit run app/main.py` на чистом клоне (после pip install) — весь сценарий п.2 проходит без ошибок.
2. Изменение заказа/резерва/инвестиции меняет баланс, расходы и нарушения (продемонстрировать 2 примера в отчёте: до/после).
3. Числа UI = числа CSV-экспорта (сверить 5 значений).
4. Невалидный план (tests/examples/invalid_plan_examples) даёт понятные русские сообщения, а не traceback.
5. Гео-модуль: после «восстановить цены» прогон BASE совпадает с исходным до символа.
