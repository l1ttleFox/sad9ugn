# INTEGRATION_CHECKLIST — чек-лист сборки и приёмки

Заполняется оркестратором после каждой волны. Порядок проверки соответствует требованию кейса: установка → BASE → обязательный стресс → дополнительные тесты → сравнение → выгрузка.

## Приёмка волны (для каждого REPORT_waveK.md)

- [ ] Отчёт существует, описывает сделанное и отклонения
- [ ] Изменения только в разрешённых промптом путях (проверить `git diff --stat main...<ветка>`)
- [ ] CASE_INPUT не изменён (`data/`, `configs/*.yaml`, `docs/*_RULES.md` — diff пуст)
- [ ] Контракты соблюдены (сигнатуры/схемы/единицы); предложения по изменению — только в отчёте
- [ ] Критерии приёмки промпта выполнены и продемонстрированы
- [ ] Новые TEAM_ASSUMPTION предложены с обоснованием (не применены самовольно)

## Интеграция WP1 (после волны 3)

- [ ] `python -m pytest tests/ -q` — все тесты V01–V10 зелёные, значения совпадают с `tests/validation/expected_checks.json`
- [ ] `run_plan` считает BASE для эталонного плана за < 5 сек
- [ ] Числа ядра совпадают с независимым ручным расчётом WP2-волны1 (расхождения < 0.5% или объяснены)
- [ ] Нарушения выводятся с rule_id, периодом, фактом, лимитом, сообщением на русском

## Интеграция WP4 (после волны 2)

- [ ] `streamlit run app/main.py` стартует без ошибок
- [ ] Пользовательский сценарий проходит без разработчика: выбрать набор → создать/изменить план → пересчитать → увидеть нарушения → переключить BASE/STRESS → сравнить → сохранить → открыть → выгрузить CSV
- [ ] Числа UI == числа экспорта == числа results/ (критерий 5)
- [ ] Ошибочный ввод даёт понятное сообщение (проверить на invalid_plan_examples)

## Финальный прогон (перед сдачей)

- [ ] Чистый клон: `git clone` → `pip install -r requirements.txt` → всё запускается
- [ ] BASE: сохранённый план в results/, SL_total ≥ 0.97 и SL_critical ≥ 0.99 по всем годам, CAPEX-лимиты, 45-дн. резерв — все hard-проверки passed
- [ ] MANDATORY_STRESS: тот же или адаптированный план; потолок потерь ≤2% с 2038; ориентир SL показан честно (нарушения с дефицитом и причиной, если есть)
- [ ] Low/high demand sensitivity — просчитаны
- [ ] Реестр рисков с рассчитанными последствиями (т, млн, SL)
- [ ] Расширяемость: на копии набора добавлены Source-X и 2041 год — система подхватила без правки кода
- [ ] Геополитический бонус-модуль (если реализован): event → параметр → пересчёт → эффект, экспорт, восстановление исходных цен
- [ ] Экспорт CSV/XLSX: scenario, периоды, единицы, assumptions_reference — по export.schema.json
- [ ] Записка 8–12 стр.: числа совпадают с results/; evidence map «источник→метод→реализация→ограничение»
- [ ] Презентация ≤12 слайдов; README с командой запуска и порядком проверки
- [ ] В репозитории нет секретов/токенов; requirements.txt с версиями
