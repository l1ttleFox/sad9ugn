## Задание

### 1. Презентация `presentation/`
≤12 слайдов (требование кейса). Формат: Markdown-слайды (Marp — `presentation.md` + сборка в PDF если доступна) ИЛИ HTML (reveal.js) — выбрать то, что собирается без платных инструментов. Структура:
1. Титул + суть решения (1 фраза: decision-support система планирования топливного контура 2035–2040).
2. Проблема и вызовы (рост спроса ×2.9, неопределённость, TOP-обязательства, lead times, CAPEX-лимиты).
3. Пользовательский сценарий оператора (скриншот-схема пути в UI).
4. Архитектура контура (данные → решения → ядро → проверки → сценарии → экспорт).
5. Сравнение альтернатив: скрининг 25 стратегий → топ-5 → финал (ключевая таблица/график из WP2; показать воронку отбора).
6. Финальная стратегия: решения, инвестиции, ворота G1–G4.
7. Экономика: PV расходов, cost/served t, CAPEX-профиль против лимитов.
8. BASE vs MANDATORY_STRESS (главные дельты: SL, shortage, расходы; резюме 1page).
9. Риски: топ-3 с рассчитанными последствиями и мерами.
10. Стейкхолдеры и адаптивность (кто что несёт, как меняется баланс при стрессе).
11. Проверяемость: V01–V10, независимый ручной расчёт, расширяемость (Source-X, 2041), экспорт.
12. Итоги: ответы на вопросы кейса (источники, резерв, гибкость, когда Луна рациональна) + ограничения.
Каждый слайд: числа из results/ (совпадение обязательно), минимум текста, подпись единиц. Тезисы спикера — в `presentation/speaker_notes.md`.

### 2. Корневой README.md (требование передачи решения)
- Назначение решения (2–3 предложения);
- состав репозитория (дерево с описанием папок);
- зависимости и версии, установка (`pip install -r requirements.txt`);
- команда запуска UI и тестов;
- ПОРЯДОК ПРОВЕРКИ из кейса: установка → стандартный сценарий → обязательный стресс → дополнительные тесты → сравнение и выгрузка (пошагово, со скриншотами/ожидаемыми числами);
- где данные, допущения (реестр TA), расчётные модули, сохранённые планы, экспорты;
- демонстрация расширяемости (как добавить Source-X/2041 на копии — команда);
- границы прототипа (что НЕ является: не система управления реальным оборудованием);
- ссылка на записку, презентацию, реестр рисков;
- команда/контакты (заполнит оркестратор).

### 3. Финальная сборка репозитория
- Проверить структуру соответствует рекомендованной кейсом: src/ data/ configs/ tests/ results/ docs/ presentation/ (+app/, +ai_workstreams/ — описать в README как «материалы разработки»).
- `requirements.txt` — финальный, с версиями (pip freeze по факту).
- Убрать мусор: временные файлы, пустые папки, .DS_Store и т.п.; `.gitignore` (venv, __pycache__, *.pyc, .streamlit/secrets).
- Проверить: нет секретов/токенов в истории и файлах.
- Свежий прогон на чистом клоне: install → pytest (зелёные) → streamlit (стартует) → FINAL-планы открываются → экспорт работает. Результат — в REPORT.
- `docs/ИСТОЧНИКИ.md` — финальный список литературы (авторы, год, DOI) — собрать из WP5, отделить материалы постановщика от самостоятельно найденных.

### 4. Отчёт
