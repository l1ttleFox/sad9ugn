# ai_workstreams — машина параллельной ИИ-разработки

Весь проект «Топливный космоконтур 2035» выполняется несколькими ИИ-моделями на разных устройствах параллельно. Эта директория — «фабрика»: замороженные контракты + самодостаточные промпты для каждого пакета работ (WP) с волнами.

- Стартовые сообщения волны 1: `START_MESSAGES.md`
- **Стартовые сообщения волны 2+: `START_MESSAGES_WAVE2.md` (порядок запуска — раздел D7)**
- **Решения оркестратора по итогам волны 1: `ORCHESTRATOR_DECISIONS.md` (обязательны для всех волн 2+)**

## Инструкция исполнителю (любая ИИ-модель, любое устройство)

1. `git clone git@github.com:l1ttleFox/sad9ugn.git && cd sad9ugn`
2. `git checkout <своя ветка>` (список выше; если ветки нет — `git checkout -b <ветка> main`).
3. Открой свой промпт: `ai_workstreams/WPN_*/prompt_waveK.md`. Прочитай ПОЛНОСТЬЮ, включая контракты в `ai_workstreams/00_contracts/` (core_api.md, plan_format.json, result_format.json, units_and_conventions.md) — они ОБЯЗАТЕЛЬНЫ.
4. Выполни задание волны. Работай ТОЛЬКО в своей ветке и ТОЛЬКО в своих файлах (границы указаны в промпте). НЕ изменяй: `ai_workstreams/00_contracts/**`, `data/**`, `configs/*.yaml`, `docs/CALCULATION_RULES.md` и прочие CASE_INPUT-файлы, чужие WP-папки.
5. Проверь себя по разделу «Критерии приёмки» промпта.
6. Напиши отчёт `ai_workstreams/WPN_*/REPORT_waveK.md`: что сделано, решения, отклонения от контрактов (если предложены — не применяй сам!), вопросы оркестратору, что передать следующей волне.
7. `git add` только свои файлы → `git commit -m "wpN: <кратко>"` → `git push origin <своя ветка>`.
8. СТОП. Следующую волну запускает другая сессия после проверки отчёта оркестратором.

## Правила качества (единые для всех)

- CASE_INPUT неизменяем; каждое допущение — в реестр TEAM_ASSUMPTION (units_and_conventions.md §12) с ID TA-XX. Новый TA предлагается в REPORT, добавляет только оркестратор.
- Числа в коде, отчётах, записке, экспорте должны совпадать (критерий 5 оценки).
- Сообщения об ошибках — на русском, с названием параметра и периода.
- Воспроизводимость: одинаковые входы → одинаковые выходы; если есть случайность — seed в meta.
- Язык: весь человекочитаемый текст — русский; идентификаторы кода и ключи JSON — английские (по схемам организатора).
- Коммиты атомарные; в сообщении префикс `wpN:`.

## Структура итогового решения (собирается оркестратором в main)

```
src/engine/       — расчётное ядро (WP1)
app/              — Streamlit UI (WP4)
configs/          — сценарии BASE/STRESS (CASE_INPUT) + TEAM_* (WP3)
data/             — CASE_INPUT + schemas (неизменяемо)
tests/            — V01–V10, интеграционные, протоколы (WP1/WP3)
results/          — сохранённые планы и выгрузки BASE/STRESS/S01–S25 (WP2/WP3)
docs/             — записка, evidence map, риски, стейкхолдеры, KPI (WP5)
presentation/     — слайды (WP6)
```

Запуск итогового решения (будет в корневом README):
```
pip install -r requirements.txt
python -m pytest tests/ -q          # контроль V01–V10 и интеграция
streamlit run app/main.py           # рабочее место оператора
```
